API documentation

Real endpoints from the OpenWA gateway (v0.23.6, 160 routes). Base URL defaults to http://localhost:2785. Every request needs your API key in the X-API-Key header.

Replace YOUR_API_KEY with the key from docker logs openwa-api, and SESSION_ID with the UUID returned when you create a session.

1. Health check

bash
curl http://localhost:2785/api/health/ready

2. Create a session

bash
curl -X POST http://localhost:2785/api/sessions \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "my-bot"}'

# → 201 {"id":"0a941dac-...","name":"my-bot","status":"created",...}

3. Pair via QR code

bash
curl http://localhost:2785/api/sessions/SESSION_ID/qr \
  -H "X-API-Key: YOUR_API_KEY"

# → 200 {"qrCode":"data:image/png;base64,...","status":"qr_ready"}
# Render the data URL as an image and scan it with WhatsApp → Linked devices.
# Alternative: POST /api/sessions/SESSION_ID/pairing-code {"phoneNumber":"628123456789"}
# → {"pairingCode":"ABCD1234","status":"qr_ready"} — enter it on your phone.

4. Send a text message

bash
curl -X POST http://localhost:2785/api/sessions/SESSION_ID/messages/send-text \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"chatId": "628123456789@c.us", "text": "Hello from NecxaWA"}'

# Individuals:  <digits>@c.us     Groups: <groupId>@g.us

5. Send image / document

bash
curl -X POST http://localhost:2785/api/sessions/SESSION_ID/messages/send-image \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"chatId":"628123456789@c.us","url":"https://example.com/photo.jpg","caption":"Look at this"}'

# send-document works the same way (adds optional "filename").
# Or send base64 inline: {"chatId":"...","base64":"...","mimetype":"image/jpeg"}

6. Webhooks (live events)

bash
curl -X POST http://localhost:2785/api/sessions/SESSION_ID/webhooks \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://your-server.com/hook","events":["*"]}'

# Your URL now receives POSTs for inbound messages, session status, etc.

7. JavaScript (fetch)

javascript
const BASE = "http://localhost:2785";
const KEY = "YOUR_API_KEY";
const headers = { "X-API-Key": KEY, "Content-Type": "application/json" };

// create session
let s = await fetch(`${BASE}/api/sessions`,
  { method: "POST", headers, body: JSON.stringify({ name: "my-bot" }) })
  .then(r => r.json());

// send text
await fetch(`${BASE}/api/sessions/${s.id}/messages/send-text`, {
  method: "POST", headers,
  body: JSON.stringify({ chatId: "628123456789@c.us", text: "Hello!" })
});
